# Makeover 2026-10 — audit, preservation checklist, log and results

Branch: `makeover/2026-10` (from `main` @ 10e61c4). Production (`main`, thecreativevault.co) untouched.

## 1. Audit of the site as found

**Stack.** Plain static site, no framework, no build on Netlify (`publish = "site"`). 54 HTML pages:
homepage, `/explore/`, `/weekly-drip/`, `/my-vault/`, 18 category pages, 10 guides, 20 comparisons + hub, 404.
Data: `site/database/**/*.json` → `tools/compile-database.js` → `site/data/generated-resources.js`
(2,267 records, 191 categories, ~250 KB brotli). Weekly Drip: GitHub Action every Sunday 12:05 UTC
writes `site/data/weekly-drip.json` from the YouTube API (secret `YOUTUBE_API_KEY` in GitHub).
Shared chrome applied by `tools/apply-chrome.mjs`; tokens in `css/tokens.css`; contrast guard
`tools/check-contrast.mjs`. Integrations actually used: GitHub, Netlify, Google Fonts, Google/DuckDuckGo
favicon services, YouTube thumbnails. **Not used:** Supabase, Cloudflare, Square, Squarespace — none were
touched.

**The "0 resources / 0 categories" bug — confirmed, root cause found, fixed.**
Not hydration, not a build or cache fault. The hero markup literally shipped
`<span id="totalCount">0</span> … <span id="totalCategories">0</span>` and relied on `app.js` to
overwrite it, which can only happen after the four data scripts at the end of `<body>` (incl. the
~250 KB generated-resources.js, served `max-age=0, must-revalidate`) download and run. So the page
painted "0 creative resources … 0 categories" whenever:
- the connection was slow (visible for the whole download — seconds on mobile),
- a script was blocked or failed (content blockers, flaky network) — it then stayed 0 forever,
- a non-JS reader looked: crawlers' first pass, link-preview bots, reader modes.

Fix: `tools/stamp-counts.mjs` writes the true numbers into every `data-stamp` element at compile time
(now part of `npm run compile`), so the HTML is right before any script runs; `app.js` still refreshes
them. If the data fails, the library shows an honest "didn't load" message instead of silence.
Verified by test with the data file blocked: hero reads 2,267, error message shown.

## 6. Remaining UX weaknesses (honest)

- Curated order clusters vendors (a run of ~30 Adobe/Autodesk records) because `featured` is dense filler; a real curation signal would fix the library's first screen more than any styling.
- Category labels are inconsistent at the data level (“Software” vs “Creative Essentials” vs “3D / CAD”), which shows in the tiles.
- Logos still depend on third-party favicon services; owning ~200 top logos would make the cards fully reliable.
- The PDF advertises 9,289 links vs 2,267 on the site — true of the file, but the difference is unexplained to visitors.
- Category/guide pages are improved but still use their older layout; a second pass could bring them to the homepage's card anatomy with live filtering.
